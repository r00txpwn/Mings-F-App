# Reliability and manual QA priorities

Use this checklist when validating releases (especially after changes to ordering, payments, delivery, or staff tools). Automated QA artifacts live in `test-results/`; this document is **manual** coverage that is hard to fully automate.

## Order and payment (`/order`)

- **Kitchen closed**: With `online_settings.is_open = false`, placing an order returns a clear error (`KITCHEN_CLOSED`); storefront maps it to localized copy.
- **Invalid quantity**: Non-integer or out-of-range quantities are rejected (`INVALID_QUANTITY`).
- **Card vs cash**: Card flows use `awaiting_payment` until Epoint succeeds; cash/COD stay `pending` as designed.
- **Return from payment**: After Epoint redirect, order state recovers (poll + URL params); combo lines send real `comboSelections`, not empty arrays.

## Customer flow

- **Address search**: Failed Places search or failed place resolution shows translated errors (not silent failure).
- **Delivery map**: Zone pill reflects idle / in-zone / out-of-zone; checkout passes polygons when zones exist.
- **Account / OTP**: Resend cooldown and auth errors use `translations` keys (en / az / ru).

## KDS (`/kds`)

- **Realtime gap**: After reconnect (banner clears), the board refetches so no orders are missing between disconnect and subscribe.
- **Status updates**: Pending → preparing → ready timestamps behave as before.

## Kiosk order manager (staff)

- **Wolt manual dispatch**: Saving tracking URL only when order is preparing or ready; duplicate save with same URL is idempotent; conflict if already dispatched with another URL.
- **Wolt booking lock**: “Open Wolt” sets a short lock; other tabs/staff see the lock after refresh or `delivery_orders` realtime; persisted lock uses `wolt_booking_locked_until` when migrations are applied.

## Database / policies

- Run new migrations on staging before prod: `delivery_orders.wolt_booking_locked_until`, tightened anon kiosk `UPDATE` on `sales` for `cancellation_reason`.
- **Payment reconciliation log** (`payment_reconciliation_log`): table exists for future reconcilers; until those jobs ship and write rows, regression focus stays on **EPoint webhook** + **`online_payments` / `sales`** behavior (unchanged by the empty log).
- **Manual `payment-reconcile` Edge Function** (after deploy + `PAYMENT_RECONCILE_SECRET`): ops-only; each call should append a **`payment_reconciliation_log`** row; wrong Bearer → **401**; verify on staging with **sandbox EPoint** before touching production rows.
